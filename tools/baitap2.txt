# PHẦN B. PHÂN TÍCH HỆ THỐNG

## B.1. Giới thiệu chung

PixelVault là hệ thống cửa hàng trực tuyến kết hợp cửa hàng game số và cửa hàng đồ chơi, mô hình hóa theo kiểu lai của Steam Store và Steam Workshop.

Công nghệ sử dụng: Node.js và Express cho máy chủ, MongoDB với Mongoose làm lớp đối tượng hóa dữ liệu, React cho giao diện một trang, Vite để đóng gói.

Hệ thống có ba vai trò người dùng: người dùng (khách hàng), nhà phát triển (đăng game, trả lời đánh giá, xem doanh thu) và quản trị viên.

## B.2. Các chức năng nghiệp vụ chính

**1. Danh mục sản phẩm và tìm kiếm.** Duyệt game và đồ chơi, lọc theo thể loại, nền tảng chạy, khoảng giá và các tính năng của game; sắp xếp theo nhiều tiêu chí; tìm kiếm toàn văn trên tên và mô tả.

**2. Giỏ hàng và thanh toán.** Thêm, xoá, đổi số lượng; tính tổng tiền gồm tiền hàng, thuế và phí vận chuyển; đặt hàng.

**3. Giao key số.** Sau khi thanh toán, hệ thống đặt trước đúng một key còn trống bằng thao tác nguyên tử, mã hoá bằng AES-256-GCM; người dùng giải mã key trong trang thư viện của mình.

**4. Thư viện và lịch sử chơi.** Danh sách game và đồ chơi đã mua, thời gian chơi, thành tựu đã mở khoá.

**5. Đánh giá và phản hồi.** Người dùng chấm điểm từ 1 đến 5 sao, đánh dấu bình luận hữu ích; nhà phát triển trả lời bình luận.

**6. Cộng đồng.** Diễn đàn chia theo mục, trả lời, thích bài, ghim và khoá bài.

**7. Mod cộng đồng.** Hiển thị mod thật được lấy từ Steam Workshop, kèm nguồn gốc và thời điểm lấy.

**8. Bảng điều khiển nhà phát triển.** Thống kê doanh thu, trả lời đánh giá, đăng game mới.

## B.3. Chức năng ngoài phạm vi

Hệ thống không xử lý thanh toán tiền thật và không phát hành key Steam thật. Các key bán ra là mã giả có dạng DEMO-XXXXX-XXXXX-XXXXX chỉ phục vụ mục đích học tập. Phí vận chuyển và thuế là giá mẫu cấu hình trong tệp môi trường, được ghi rõ là giá mẫu ngay trên màn hình thanh toán.

# PHẦN C. BIỂU ĐỒ QUAN HỆ DỮ LIỆU THEO HƯỚNG ĐỐI TƯỘNG

## C.1. Quan niệm mô hình

Trong hướng đối tượng, khóa chính không phải khóa ngoại dạng số mà là tham chiếu tới đối tượng khác. Mỗi lớp đối tượng dưới đây ánh xạ thành đúng một collection. Các quan hệ được phân loại:

Quan hệ kế thừa hoặc hợp thành (composition): đối tượng con chỉ tồn tại cùng đối tượng cha. Thể hiện bằng cách nhúng tài liệu con vào trong tài liệu cha.

Quan hệ liên kết (association): hai đối tượng độc lập về vòng đời, liên kết bằng tham chiếu khóa. Thể hiện bằng trường ObjectId.

Quan hệ kế thừa dữ liệu: hai collection cùng phục vụ một khái niệm, dùng chung một trường phân loại. Trong hệ thống này là trường productType của collection games.

## C.4. Ba quyết định thiết kế cần giải thích

**Quyết định 1. Nhúng library thay vì tách collection riêng.**

Quan hệ giữa người dùng và mục thư viện là quan hệ hợp thành: một mục thư viện không tồn tại nếu không có người dùng sở hữu nó, nó không có ý nghĩa nào ngoài người dùng đó, và nó luôn được đọc cùng lúc với thông tin người dùng khi mở trang hồ sơ. Nhúng vào giúp tránh phép nối và giữ tính nhất quán dữ liệu. Ngược lại, đánh giá là một thực thể độc lập vì hệ thống cần truy vấn toàn bộ đánh giá của một game mà không phụ thuộc vào người dùng nào, nên tách thành collection riêng.

**Quyết định 2. Tách collection gamekeys riêng thay vì nhúng vào games.**

Vì cần thao tác khóa ở mức từng bản ghi. Khi thanh toán, hệ thống phải lấy đúng một key còn trống. Nếu nhúng mảng key vào tài liệu game, hai yêu cầu thanh toán đồng thời có thể cùng đọc thấy phần tử đầu tiên và bán trùng cho hai người. Tách thành collection riêng cho phép dùng phương thức findOneAndUpdate, là thao tác nguyên tử ở tầng tài liệu của MongoDB, nên không thể xảy ra bán trùng.

**Quyết định 3. Nhúng items vào orders thay vì trỏ tới games.**

Vì đơn hàng phải là một bản chụp trạng thái tại thời điểm mua. Tên sản phẩm và giá đơn vị phải được lưu lại nguyên vẹn. Nếu chỉ lưu tham chiếu game, thì khi game được đổi tên hoặc tăng giá, toàn bộ lịch sử đơn hàng cũ sẽ bị sai lệch theo.

## D.2. Collection users

**Chức năng phục vụ:** đăng ký, đăng nhập, phân quyền ba vai trò; thư viện game và đồ chơi đã mua; danh sách yêu thích; địa chỉ giao hàng; hồ sơ nhà phát triển gồm tên studio, email nhận tiền và số dư còn phải nhận; tuỳ chọn cá nhân gồm thể loại yêu thích và bộ lọc nội dung người lớn.

Cấu trúc tài liệu, gồm 25 trường cấp 1:

```
{
  username:       String,          // duy nhất, 3 đến 24 ký tự
  displayName:    String,
  email:          String,          // duy nhất, tự chuyển chữ thường
  phone:          String,
  passwordHash:   String,          // bcrypt, KHÔNG lưu mật khẩu thô
  role:           String,          // enum: user | developer | admin
  avatar:         String,
  bio:            String,
  wallet:         Number,          // số dư ví nội bộ
  wishlist:       [ObjectId Game],
  toyWishlist:    [ObjectId Toy],
  library:        [ {              // mục thư viện game, nhúng
     game:         ObjectId,       // bắt buộc
     edition:      String,         // digital | physical | deluxe
     purchasedAt:  Date,
     playMinutes:  Number,
     lastPlayedAt: Date,
     achievements: [ { key: String, unlockedAt: Date } ],
     completed:    Boolean
  } ],
  toyLibrary:     [ { toy: ObjectId, purchasedAt: Date, qty: Number } ],
  addresses:      [ { _id, label, fullName, street, city, region,
                       postal, country, phone } ],
  playHistory:    [ { game: ObjectId, minutes: Number, playedAt: Date } ],
  purchaseHistory:[ ObjectId Order ],
  devProfile:     { studioName, website, payoutEmail, verified, balanceOwed },
  preferences:    { favoriteGenres: [String], matureFilter: Boolean },
  createdAt: Date, updatedAt: Date
}
```

**Chỉ mục tạo trên collection này:**

| Chỉ mục | Loại | Lý do |
|---|---|---|
| username_1 | duy nhất | chống trùng tên đăng nhập |
| email_1 | duy nhất | chống trùng email, phục vụ đăng nhập |

## D.3. Collection games

**Chức năng phục vụ:** toàn bộ danh mục game gồm trang chủ, trang cửa hàng và trang chi tiết; bộ lọc theo thể loại, tính năng, nền tảng và khoảng giá; năm kiểu sắp xếp; tìm kiếm toàn văn; quản lý tồn kho key thông qua stats.keysAvailable; thống kê doanh thu và số lượng bán; hiển thị điểm đánh giá trung bình.

Cấu trúc tài liệu, gồm 65 trường cấp 1 và 4 tài liệu con:

```
{
  title: String,                   // bắt buộc
  slug:  String,                   // duy nhất, tự sinh từ title
  tagline: String, description: String,
  developer: ObjectId,             // trỏ tới users, bắt buộc
  studioName: String,
  genres:    [String],             // có chỉ mục
  tags:      [String],
  platforms: [String],             // enum: Windows Mac Linux Steam Deck VR
  features:  [String],             // danh mục tính năng của Steam
  coverImage: String, screenshots: [String], trailerUrl: String,
  price: Number,                   // bắt buộc, không nhỏ hơn 0
  discountPct: Number,             // từ 0 đến 90
  digitalSku: String,
  steamAppId: Number,              // có chỉ mục, sparse
  productType: String,             // enum game | toy, có chỉ mục

  systemReq: {                     // tài liệu con: yêu cầu hệ thống
    minimum:     Map<platform, String>,
    recommended: Map<platform, String>,
    lines:       Map<platform, [String]>,
    source: String
  },
  physical: {                      // tài liệu con: bản đĩa vật lý
    enabled: Boolean, price: Number, stock: Number,
    weightLb: Number, warehouse: String, includes: [String]
  },
  toy: { brand, category, material, size, age, relatedAppId },
  stats: {                         // tài liệu con: số liệu tổng hợp
    views, unitsDigital, unitsPhysical, revenueGross,
    reviewSum, reviewCount,        // dùng tính avgRating
    keysAvailable, keysSold
  },
  publisher: String, languages: Number, categories: [String],
  contentWarnings: [String], deckVerified: String,
  status:   String,                // enum draft pending published rejected delisted
  featured: Boolean,
  releaseDate: Date,               // có chỉ mục giảm dần
  modSupport: Boolean,
  sourceUrl: String, fileSizeGB: Number, version: String, rating: String,
  createdAt: Date, updatedAt: Date
}
```

**Thuộc tính tính toán, không lưu trong cơ sở dữ liệu:**

| Thuộc tính | Công thức | Dùng để |
|---|---|---|
| salePrice | giá nhân với một trừ phần trăm giảm giá | hiển thị giá sau khuyến mại |
| avgRating | tổng điểm đánh giá chia cho số đánh giá | hiển thị sao trung bình |

**Một lưu ý quan trọng về nguyên tắc không bịa dữ liệu.** Cửa hàng Steam không công bố dung lượng cài đặt, số phiên bản phần mềm, và xếp hạng độ tuổi theo chuẩn ESRB. Vì vậy ba trường fileSizeGB, version và rating trong lược đồ **không được đặt giá trị mặc định**. Nếu đặt mặc định kiểu version bằng 1.0.0, hệ thống sẽ âm thầm tạo ra một con số trông như dữ liệu thật; tệ hơn, chức năng ẩn nội dung người lớn lọc đúng trường rating nên sẽ hỏng âm thầm vì mọi game đều cùng một xếp hạng. Khi nguồn không có dữ liệu, hệ thống để trống và giao diện hiển thị chưa công bố.

## D.5. Collection gamekeys

**Chức năng phục vụ:** lưu trữ kho key số đã mã hoá; cấp key an toàn khi thanh toán; ngăn bán trùng; ngăn bán lại key đã bán; chứng minh sở hữu key bằng giá trị băm; truy vết key của một đơn hàng và của một người dùng.

Đây là collection nhạy cảm nhất vì chứa bí mật của người mua.

```
{
  game:     ObjectId,          // trỏ tới Game, bắt buộc, có chỉ mục
  batchId:  String,            // mã lô nhập, có chỉ mục
  platform: String,            // enum Steam Epic GOG PixelVault
  region:   String,
  codeEnc:  String,            // BẮT BUỘC - mã hoá AES-256-GCM, định dạng iv.tag.data
  codeHash: String,            // BẮT BUỘC - SHA-256 của bản rõ, DUY NHẤT
  status:   String,            // enum available reserved sold revoked, có chỉ mục
  order: ObjectId,             // null khi key chưa bán
  user:  ObjectId,             // null khi key chưa bán
  soldAt: Date,
  createdAt: Date, updatedAt: Date
}
```

**Nguyên tắc bảo mật:** hệ thống không bao giờ lưu key ở dạng rõ. Trường codeEnc lưu bản mã hoá AES-256-GCM; trường codeHash lưu giá trị băm SHA-256 để chống trùng mà không cần giải mã. Khoá mã hoá được đọc từ biến môi trường KEY_ENCRYPTION_SECRET; nếu thiếu biến này, hệ thống báo lỗi ngay lập tức chứ không dùng một giá trị dự phòng viết cứng trong mã nguồn.

**Cơ chế chống bán trùng, chống cạnh tranh:**

```javascript
// Đặt trước nguyên tử đúng một key còn trống cho một game
GameKey.claimOne = function (gameId, { orderId = null, userId = null } = {}) {
  return this.findOneAndUpdate(
    { game: gameId, status: 'available' },     // điều kiện lọc
    { $set: { status: 'sold', order: orderId,
              user: userId, soldAt: new Date() } },
    { new: true }
  );
};
```

Phương thức findOneAndUpdate là thao tác nguyên tử ở tầng tài liệu của MongoDB: hai yêu cầu thanh toán phát ra đồng thời không thể cùng nhận một key, vì chỉ một yêu cầu khớp điều kiện status bằng available mới cập nhật được.

# PHẦN F. TẠO CẤU TRÚC COLLECTION TRONG MONGODB

## F.1. Công cụ định nghĩa lược đồ

Hệ thống dùng thư viện Mongoose để định nghĩa cấu trúc. Mỗi tệp lược đồ trong thư mục models ánh xạ thành một collection.

::: 2 2 6
| Tệp lược đồ | Collection | Đặc điểm đáng chú ý |
|---|---|---|
| User.js | users | có phương thức ownsGame và totalPlayMinutes |
| Game.js | games | có tài liệu con, thuộc tính tính toán, middleware sinh slug |
| Toy.js | toys | có middleware sinh slug, chỉ mục toàn văn |
| GameKey.js | gamekeys | có hàm tĩnh claimOne và countAvailable |
| Order.js | orders | có hai tài liệu con nhúng là items và shipment |
| Review.js | reviews | chỉ mục duy nhất trên cặp game và user |
| Mod.js | mods | có tài liệu con source và mirror |
| Post.js | posts | có tài liệu con replies nhúng |

## F.2. Đoạn mã minh hoạ trích từ lược đồ gamekeys

```javascript
const mongoose = require('mongoose');

const keySchema = new mongoose.Schema({
  game:   { type: mongoose.Schema.Types.ObjectId, ref: 'Game',
             required: true, index: true },
  batchId:{ type: String, default: 'seed', index: true },
  platform: { type: String, enum: ['Steam', 'Epic', 'GOG', 'PixelVault'],
              default: 'Steam' },
  region:   { type: String, default: 'GLOBAL' },
  // bản mã hoá AES-256-GCM, định dạng iv.tag.data
  codeEnc:  { type: String, required: true },
  // SHA-256 của bản rõ, duy nhất, chống nạp trùng
  codeHash: { type: String, required: true, unique: true },
  status:   { type: String, enum: ['available', 'reserved', 'sold', 'revoked'],
              default: 'available', index: true },
  order: { type: mongoose.Schema.Types.ObjectId, ref: 'Order', default: null },
  user:  { type: mongoose.Schema.Types.ObjectId, ref: 'User',  default: null },
  soldAt:{ type: Date, default: null },
}, { timestamps: true });

keySchema.index({ game: 1, status: 1 });

// Đặt trước nguyên tử đúng một key còn trống, an toàn cạnh tranh
keySchema.statics.claimOne = function (gameId, { orderId = null, userId = null } = {}) {
  return this.findOneAndUpdate(
    { game: gameId, status: 'available' },
    { $set: { status: 'sold', order: orderId, user: userId,
              soldAt: new Date() } },
    { new: true }
  );
};

module.exports = mongoose.model('GameKey', keySchema);
```

## F.3. Middleware tự sinh slug

Slug là định dạng đường dẫn thân thiện cho tên sản phẩm, ví dụ terraria-abc123. Slug được sinh tự động khi người dùng không nhập:

```javascript
gameSchema.pre('validate', function (next) {
  if (!this.slug && this.title) {
    this.slug = this.title.toLowerCase()
      .replace(/[^a-z0-9]+/g, '-')
      .replace(/^-|-$/g, '')
      + '-' + Date.now().toString(36);
  }
  next();
});
```

## F.4. Lệnh tạo collection trên cơ sở dữ liệu đang chạy

MongoDB tạo collection theo kiểu chậm: collection chỉ tồn tại sau khi có tài liệu đầu tiên. Để chủ động tạo toàn bộ collection và toàn bộ chỉ mục:

```javascript
const mongoose = require('mongoose');
const db = mongoose.connection.db;

// Bước 1: tạo đủ tám collection
const names = ['users', 'games', 'toys', 'gamekeys',
               'orders', 'reviews', 'mods', 'posts'];

for (const name of names) {
  const exists = await db.listCollections({ name }).hasNext();
  if (exists) {
    console.log(name + ': đã tồn tại');
  } else {
    await db.createCollection(name);
    console.log(name + ': đã tạo mới');
  }
}

// Bước 2: tạo chỉ mục đúng theo lược đồ
await mongoose.model('User').syncIndexes();
await mongoose.model('Game').syncIndexes();
await mongoose.model('Toy').syncIndexes();
await mongoose.model('GameKey').syncIndexes();
await mongoose.model('Order').syncIndexes();
await mongoose.model('Review').syncIndexes();
await mongoose.model('Mod').syncIndexes();
await mongoose.model('Post').syncIndexes();
```

Lệnh tương đương trong trình quản lý trực quan như MongoDB Compass hoặc Navicat: kết nối vào cơ sở dữ liệu pixelvault, chọn Indexes trên từng collection, rồi tạo chỉ mục với các thuộc tính tương ứng với bảng ở mục F.5.

# PHẦN G. THÊM DỮ LIỆU VÀO CÁC COLLECTION

## G.1. Nguyên tắc lấy dữ liệu

Toàn bộ số liệu trên cửa hàng đến từ giao diện lập trình chính thức của Steam, không phải dữ liệu tự nghĩ ra.

::: 4 6
| Dữ liệu | Nguồn |
|---|---|
| tên game, hãng phát triển, thể loại, giá, phần trăm giảm giá, ngày phát hành, nền tảng chạy | giao diện lập trình Steam Store |
| yêu cầu hệ thống tối thiểu và khuyến nghị, theo từng hệ điều hành | trường pc_requirements, mac_requirements, linux_requirements |
| ảnh bìa và ảnh nền | máy chủ ảnh của Steam, chọn bản lớn nhất mà mã game có |
| danh mục tính năng như một người chơi, chơi chung, thành tựu | trường categories của Steam |
| mod, số liệu Steam và nguồn của mod | trang Steam Workshop |
| tên, thương hiệu, giá, tồn kho của đồ chơi | trang bán hàng chính thức của nhà sản xuất |
| số liệu tổng hợp, tồn kho, tổng tiền đơn hàng, doanh thu | đếm trực tiếp từ chính cơ sở dữ liệu MongoDB |

**Nguyên tắc quan trọng: khi nguồn không có dữ liệu thì để trống, không dựng ra một con số trông hợp lý.** Ví dụ Steam không công bố dung lượng cài đặt, số phiên bản, xếp hạng độ tuổi, nên ba trường đó không có giá trị mặc định trong lược đồ và giao diện hiển thị chưa công bố.

## G.3. Ví dụ chuyển đổi dữ liệu Steam thành tài liệu games

```javascript
const price = d.is_free ? 0
  : (d.price_overview && Number.isFinite(d.price_overview.final)
      ? d.price_overview.final / 100
      : null);   // KHÔNG dựng giá 19.99 khi Steam không có giá

return {
  title: d.name,
  tagline: (d.short_description || '').slice(0, 160),
  studioName: (d.developers && d.developers[0]) || 'Unknown studio',
  genres:    genres.length ? genres : ['Indie'],
  platforms,                       // lấy từ d.platforms
  features:  cats,                 // danh mục tính năng của Steam
  coverImage: art.cover,           // bản ảnh lớn nhất có sẵn
  screenshots: [art.hero, ...shots].filter(Boolean),
  price, discountPct: discount,
  digitalSku: `PV-STEAM-${appid}`,
  steamAppId: appid,
  // Steam không công bố ba trường dưới, để trống thay vì bịa
  fileSizeGB: undefined,
  version:    undefined,
  rating:     undefined,
  systemReq:  {},                  // enrich-steam.js sẽ điền sau
  status: 'published',
  releaseDate: d.release_date?.date ? new Date(d.release_date.date) : undefined,
  developer: devId,
};
```

## G.4. Mã hoá key khi nạp dữ liệu

```javascript
const { encryptKey, hashKey, makeDemoKey } = require('../lib/keyCrypto');

const plain = makeDemoKey('DEMO');   // ví dụ DEMO-06883-4B6C5-42C30

await GameKey.create({
  game: gameId,
  batchId: 'import-2026-10',
  platform: 'Steam',
  codeEnc:  encryptKey(plain),       // mã hoá AES-256-GCM
  codeHash: hashKey(plain),          // SHA-256, có chỉ mục duy nhất
  status: 'available',
});
```

**Lưu ý về bản quyền.** Hệ thống chỉ sử dụng hình minh hoạ và thông tin mô tả từ Steam. Mọi mã key bán ra đều là mã giả có dạng DEMO-XXXXX-XXXXX-XXXXX, tuyệt đối không phải key Steam thật, nhằm phục vụ mục đích học tập và không dùng để kích hoạt phần mềm.

## G.6. Ví dụ truy vấn tổng hợp bằng đường ối tổng hợp

```javascript
// Thống kê số lượng game theo từng thể loại
await Game.aggregate([
  { $unwind: '$genres' },
  { $group: { _id: '$genres', soLuong: { $sum: 1 } } },
  { $sort: { soLuong: -1 } },
  { $limit: 10 }
]);

// Doanh thu và phần chia cho từng nhà phát triển
await Order.aggregate([
  { $unwind: '$devPayouts' },
  { $group: {
      _id: '$devPayouts.developer',
      tongDoanhThu: { $sum: '$devPayouts.gross' },
      tongChia:      { $sum: '$devPayouts.cut' },
      soDon:         { $sum: 1 }
  }},
  { $sort: { tongDoanhThu: -1 } }
]);

// Số key đã bán theo từng game
await GameKey.aggregate([
  { $match: { status: 'sold' } },
  { $group: { _id: '$game', soKeyDaBan: { $sum: 1 } } },
  { $sort: { soKeyDaBan: -1 } }
]);

// Tổng số key còn trống, dùng để hiển thị bảng số liệu tổng hợp
await Game.aggregate([
  { $group: { _id: null, tongKey: { $sum: '$stats.keysAvailable' } } }
]);

// Top game theo số lượt xem, chỉ lấy game đã xuất bản
await Game.find({ status: 'published' })
  .sort({ 'stats.views': -1 })
  .limit(10)
  .select('title stats.views stats.revenueGross');
```
